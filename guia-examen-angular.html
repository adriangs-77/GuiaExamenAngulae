1 Entorno de trabajo

Instalación del entorno

Una aplicación Angular necesita dos piezas base: Node.js (que aporta el entorno de ejecución y npm) y el Angular CLI (la herramienta de línea de comandos con la que se crea, ejecuta y compila el proyecto).

Paso 1 · Descargar Node.js desde el Prebuilt Installer

El Prebuilt Installer es el instalador ya compilado y listo para usar que se descarga desde <nodejs.org>; no hay que compilar nada. Incluye node y npm en la misma instalación.

  • Windows: archivo .msi (Windows Installer).
  • macOS: archivo .pkg.
  • Linux: binarios .tar.xz o el gestor de paquetes de la distribución.

Se recomienda elegir la versión LTS (soporte a largo plazo) que cumpla los requisitos de Angular 22. Durante la instalación hay que dejar marcada la opción de añadir Node al PATH para poder usar node y npm desde cualquier terminal.

Compatibilidad: Angular 22 y Node.js

Para Angular 22 hay que utilizar una versión de Node.js compatible con la versión instalada del framework. Si la versión no encaja, el CLI se detiene con un error de versión no soportada.

AngularNode.js compatibleTypeScriptObservación

21.x ^20.19.0 · ^22.12.0 · ^24.0.0 5.9.x Versión de transición.
20.x ^20.19.0 · ^22.12.0 · ^24.0.0 5.8.x Fin de soporte.

Error típico de versión

2 Primer proyecto

Crear y ejecutar el proyecto

Con el entorno listo, el siguiente paso es generar el proyecto con ng new, entender las preguntas del CLI y arrancar el servidor de desarrollo con ng serve.

Crear el proyecto: ng new

  1. Navegar a la carpeta donde se quiere crear el proyecto (cd).
  2. Ejecutar el comando de creación con el nombre del proyecto.

Angular crea actualmente los proyectos utilizando componentes standalone por defecto. Por eso en los proyectos nuevos normalmente no existe app.module.ts.

Do you want to create a zoneless application? Modo sin Zone.js: la detección de cambios se apoya en signals. Según el proyecto; en Angular 22 es la dirección recomendada.
Do you want to enable AI tooling / config files? Añadir ficheros de configuración para asistentes de IA. No, irrelevante para el examen.

Uso de otros componentes

En Angular moderno los componentes se importan directamente en la propiedad imports del componente que los va a usar. No hace falta ningún NgModule.

⛔
Error común

Si se usa <app-usuario> sin añadirlo a imports, Angular muestra el error 'app-usuario' is not a known element. La solución no es tocar declarations (no existe en standalone), sino importar la clase.

Componentes standalone

  • Desde Angular 19 los componentes son standalone por defecto.
  • Un componente standalone no necesita declararse dentro de un NgModule.
  • Puede importar directamente otros componentes, directivas, pipes o módulos mediante la propiedad imports.
  • Se puede usar en cualquier plantilla simplemente importándolo donde se necesita.
💡
Truco de examen

Regla mental: lo que la plantilla usa, va en imports. Si la plantilla tiene [(ngModel)] → FormsModule; si tiene *ngIf → NgIf o CommonModule; si tiene <router-outlet> → RouterOutlet.

4 Datos entre clase y vista

Binding

El binding conecta los datos del componente con la vista: permite que los datos del componente se representen o modifiquen desde el HTML. Angular actualiza la interfaz cuando cambian los datos que utiliza la plantilla.

Los cuatro tipos de binding

TipoSintaxisDirecciónEjemplo
Interpolation {{ expresión }} Componente → Vista {{ nombre }}
Property Binding [propiedad]="expresión" Componente → Vista (DOM) [src]="imagenUrl"
Event Binding (evento)="método()" Vista → Componente (click)="saludar()"
Two-way Binding [(propiedad)]="valor" Ambas direcciones [(ngModel)]="nombre"

Interpolation (Interpolación)

Descripción: enlace unidireccional que muestra datos en la vista. Se escribe con dobles llaves y admite expresiones de TypeScript (operaciones, ternarios, llamadas a métodos).

⚠️
Qué no va dentro de {{ }}

Solo expresiones, no sentencias: no se permite {{ let x = 1 }}, ni if, ni new Fecha(), ni asignaciones como {{ contador++ }}.

Property Binding

Descripción: asigna valores del componente a propiedades del DOM o de otros componentes. Se usan corchetes alrededor del nombre de la propiedad.

ℹ️
Atributo vs propiedad

[src] escribe en la propiedad del DOM, que es la que el navegador usa de verdad. Si se escribe src="{{ imagenUrl }}" también funciona, pero lo idiomático y recomendado es el property binding con corchetes.

Event Binding

Descripción: escucha eventos y ejecuta funciones. El nombre del evento va entre paréntesis. Se puede recibir el evento con $event.

Two-way Binding

Descripción: sincronización de datos en ambas direcciones. La sintaxis [()] combina property binding y event binding (se le llama «banana in a box»).

5 Estado reactivo

Signals

Los Signals son el sistema reactivo de Angular para gestionar estado. Un signal almacena un valor y Angular puede detectar qué partes de la aplicación dependen de ese valor. Cuando cambia el signal, Angular actualiza automáticamente los consumidores que dependen de él.

¿Qué son los Signals?

  • Un signal es una función que envuelve un valor y avisa cuando cambia.
  • Se leen llamándolos como una función: contador(), con paréntesis.
  • Angular registra qué plantillas y qué computed/effect consumen cada signal.
  • El seguimiento es granular: solo se actualiza lo que depende del signal que cambió.

Modificar un Signal con set()

set() sustituye directamente el valor actual.

Modificar un Signal con update()

update() calcula el nuevo valor a partir del valor anterior.

💡
Diferencia clave

set(x) → «el valor pasa a ser x».
update(fn) → «el valor pasa a ser fn(valorActual)». Si el nuevo valor es igual al anterior, el signal no notifica el cambio.

Signals calculados con computed()

computed() permite crear un valor que depende de uno o varios signals. El valor calculado se actualiza cuando cambian sus dependencias. Un computed es de solo lectura.

  • Es perezoso: solo recalcula cuando se lee y alguna dependencia cambió.
  • Es memorizado: si se lee varias veces sin cambios, devuelve el valor guardado.
  • No se le puede hacer set() ni update(): se deriva, no se asigna.

effect()

effect() permite ejecutar una acción cuando cambian los signals que utiliza. Se utiliza principalmente para efectos secundarios, por ejemplo:

  • Registrar información en consola o en un servicio de logs.
  • Guardar un valor en localStorage.
  • Sincronizar con APIs del navegador (título de la página, canvas, etc.).

No debe utilizarse como sustituto de computed() para calcular valores derivados.

ℹ️
Detalles de effect()

Se ejecuta al menos una vez al crearse y después cada vez que cambia un signal leído dentro. Debe crearse en un contexto de inyección (constructor o inicializador de campo). Angular lo destruye solo cuando muere el componente.

Ejemplo completo: contador con Signals

Resumen de la API de Signals

FunciónQué haceEjemplo
signal(valor)Crea un estado reactivo.contador = signal(0)

Trampa de examen

computed no se puede escribir, y un effect no devuelve valores. Si la pregunta dice «valor derivado que se actualiza solo» → computed; si dice «acción al cambiar un signal» → effect.

14 Pon a prueba

Autoexamen

Treinta y cinco preguntas sobre todo el temario. Intenta responder mentalmente y pulsa cada pregunta para comprobar la respuesta.

Instalación y proyecto

1. ¿Qué dos comandos comprueban la instalación de Node.js y npm?

node -v y npm -v. La opción -v muestra la versión.

2. ¿Qué versiones de Node.js son compatibles con Angular 22?

^22.22.3, ^24.15.0 o ^26.0.0. Node 20 ya no está soportado, y el CLI falla si se usa.

3. ¿Qué es el Prebuilt Installer de Node.js?

El instalador ya compilado que se descarga desde nodejs.org (por ejemplo .msi en Windows o .pkg en macOS). No hay que compilar el código fuente e incluye npm.

4. ¿Qué comando instala Angular CLI de forma global y cómo se verifica?

npm install -g @angular/cli y después ng version.

5. Escribe la secuencia para crear y arrancar un proyecto llamado PrimerProyecto.

cd carpeta → ng new PrimerProyecto → cd PrimerProyecto → ng serve --open.

6. ¿En qué URL sirve la aplicación ng serve por defecto y cómo se cambia el puerto?

En http://localhost:4200/. Se cambia con ng serve --port 4500 (o -p 4500).

7. ¿Qué diferencia hay entre ng serve y ng serve --open?

--open (abreviatura -o) abre automáticamente el navegador al terminar la compilación. El servidor es el mismo.

Componentes

8. ¿Qué comando genera el componente usuario y cuál es su forma abreviada?

ng generate component usuario, abreviado como ng g c usuario.

9. ¿Qué archivos crea ng g c usuario?

usuario.ts, usuario.html, usuario.css y usuario.spec.ts, dentro de la carpeta usuario/.

10. Nombra los metadatos principales de @Component.

selector, templateUrl, styleUrl e imports. También existen template y styles en línea.

11. ¿Desde qué versión los componentes son standalone por defecto y qué implica?

Desde Angular 19. Implica que no hace falta declararlos en un NgModule ni escribir standalone: true: importan lo que necesitan mediante imports.

12. ¿Por qué aparece 'app-usuario' is not a known element?

Porque el componente que usa esa etiqueta no tiene Usuario en su propiedad imports.

Binding y estado

13. Enumera los cuatro tipos de binding con su sintaxis y dirección.

Interpolación {{ valor }} (componente → vista) · Property binding [prop]="valor" (componente → vista) · Event binding (click)="metodo()" (vista → componente) · Two-way binding [(ngModel)]="valor" (ambas direcciones).

14. ¿Qué hay que importar para usar [(ngModel)] en un componente standalone?

FormsModule de @angular/forms, añadido al arreglo imports del componente.

15. ¿Cómo se lee el valor de un signal llamado contador?

Invocándolo como función: this.contador() en la clase y {{ contador() }} en la plantilla.

16. Diferencia entre set() y update().

set(v) sustituye el valor por v; update(fn) calcula el nuevo valor a partir del anterior, por ejemplo update(v => v + 1).

17. ¿Se puede modificar un computed con set()?

No. Un computed es de solo lectura: se recalcula automáticamente cuando cambian los signals de los que depende.

18. ¿Para qué sirve effect() y para qué no debe usarse?

Para ejecutar efectos secundarios cuando cambian los signals que lee (logs, localStorage, APIs del navegador). No debe usarse como sustituto de computed() para calcular valores derivados.

19. Escribe un signal contador que empiece en 0 y otro doble que sea el doble.

contador = signal(0); y doble = computed(() => this.contador() * 2);

Plantillas

20. Reescribe *ngIf="esVisible; else noVisible" con sintaxis moderna.

@if (esVisible) { … } @else { … }. Ya no hace falta <ng-template #noVisible>.

21. ¿Es obligatorio track en @for? ¿Qué variables internas existen?

Sí, es obligatorio. Variables: $index, $first, $last, $even, $odd y $count.

22. ¿Cuándo usar track $index y cuándo track usuario.id?

$index para colecciones estáticas sin identidad propia; usuario.id para listas de objetos que pueden cambiar de orden, filtrarse o recibir nuevos elementos, porque permite reutilizar los nodos correctos.

23. ¿Qué muestra el bloque @empty?

El contenido alternativo cuando la colección del @for está vacía, sin necesidad de un @if adicional.

24. ¿Hay que importar CommonModule para usar @if o @for?

No. Están integrados en la sintaxis de plantillas de Angular. CommonModule solo hace falta para las directivas clásicas *ngIf, *ngFor, ngClass, etc.

Routing y comunicación

25. ¿Qué tres elementos básicos del router debes conocer y qué hace cada uno?

Routes: arreglo que asocia path con componente. RouterOutlet: área donde se renderiza el componente activo. RouterLink: navegación sin recargar. Además, ActivatedRoute lee la ruta activa y Router navega por código.

26. ¿Para qué sirve la ruta path: '**' y dónde debe colocarse?

Es la ruta comodín (404): captura cualquier URL no definida. Debe ir siempre al final del arreglo, porque el router usa la primera coincidencia.

27. ¿Qué hace loadComponent y qué ventaja tiene?

Carga un componente standalone de forma diferida (lazy loading): su código se descarga solo al navegar a esa ruta, lo que reduce el tamaño inicial de la aplicación.

28. ¿Qué guard sustituye a CanLoad y qué tipos de guard existen?

CanLoad está deprecado y lo sustituye CanMatch. Los tipos principales son CanActivate, CanActivateChild, CanDeactivate y CanMatch.

29. ¿Cómo se comunica un hijo con su padre en Angular moderno?

Con output(): el hijo declara notificar = output<string>() y llama a emit(); el padre escucha con (notificar)="metodo($event)". La API clásica es @Output() + EventEmitter.

NgModules, formularios y servicios

30. Diferencia entre declarations e imports en un NgModule.

declarations registra los componentes, directivas y pipes que pertenecen al módulo; imports trae otros módulos cuyas declaraciones necesita. Un componente standalone no se declara en ningún módulo.

31. ¿Qué tres clases forman la API reactiva de formularios?

FormControl (un campo), FormGroup (grupo de campos) y FormArray (lista dinámica de controles). Se importa ReactiveFormsModule.

32. ¿Cómo se declara un campo obligatorio de al menos 3 caracteres?

new FormControl('', [Validators.required, Validators.minLength(3)]), o con FormBuilder: ['', [Validators.required, Validators.minLength(3)]].

33. ¿Qué diferencias hay entre providedIn: 'root' y registrar el servicio en providers de un componente?

providedIn: 'root' crea una única instancia para toda la aplicación. En providers del componente, el servicio tiene alcance en ese componente y sus hijos, con una instancia nueva por cada instancia del componente.

34. ¿Qué dos formas de inyección de dependencias existen y cuál es la moderna?

Por constructor (constructor(private logger: LoggerService)) y con la función inject() (private logger = inject(LoggerService)), que es la recomendada en Angular moderno.

35. ¿Qué debe hacer un componente que se suscribe a un observable que no se completa?

Cancelar la suscripción al destruirse, con ngOnDestroy o con takeUntilDestroyed(), para evitar fugas de memoria.
